# BDLMiner V2 2.6.4

## Suivi privé : migration Supabase

- Les statistiques publiques anonymes ont été migrées vers Supabase en v2.6.3. Cette version termine la migration en déplaçant aussi le suivi privé **Mes mineurs** vers Supabase.
- Le suivi facultatif **Mes mineurs** envoie désormais les relevés à une autre fonction Edge Supabase. L'accès par adresse de paiement et les clés privées de 64 caractères conservent leur fonctionnement ; l'adresse ou la clé brute n'est pas stockée dans les nouvelles tables.
- Les rapports publics agrégés et les mesures privées par appareil sont stockés séparément. Les noms privés, identifiants pseudonymes et mesures détaillées ne rejoignent jamais l'agrégat public.
- L'ancien serveur SQLite/Caddy et le relais Cloudflare ne sont plus nécessaires. Le firmware 2.6.3 envoie déjà les statistiques publiques vers Supabase, mais utilise encore l'ancien endpoint privé ; les versions antérieures à 2.6.3 utilisent aussi l'ancien endpoint public. Passe en 2.6.4 pour les deux ; aucune passerelle de compatibilité n'est fournie.
- Le rapport public anonyme reste limité à la version du firmware, la carte, le hashrate, l'intervalle, la cryptomonnaie et, éventuellement, le groupe de pool publique et le modèle. Il ne contient ni adresse de paiement, ni worker, ni hôte de pool privée, ni identifiant d'appareil.

## Mise à jour

Utiliser la mise à jour GitHub signée ou le fichier `<board>-firmware.bin` correspondant via le tableau de bord local pour conserver les réglages. Le fichier `<board>-factory.bin` sert à une première installation USB et peut effacer la configuration.

## Validation et limites connues

- Le collecteur public Supabase a répondu HTTP 200 pour les routes de contrôle et de lecture, et HTTP 204 pour un rapport anonyme valide.
- Le nouvel endpoint privé Supabase a été testé pour les rapports par clé et par adresse, la lecture des mineurs, l'historique, la révocation et le rejet d'une clé révoquée. Les données de test ont été supprimées après validation.
- La CI doit valider les derniers commits firmware et site, les images signées et le workflow de publication avant diffusion. Un test backend ne remplace pas un essai sur carte réelle.
- Lors du premier essai réel, le M5StickC Plus2 a transmis environ 480–505 kH/s, alors qu'il affichait auparavant environ 1 MH/s. **La cause n'est pas établie.** Vérifier `/api/stats` : `power_percent`, `limitation_reason`, `throttle`, `temp_c` et `engines`. Cette version ne prétend pas corriger ou améliorer le hashrate.
- L'ancien historique privé du serveur SQLite n'est pas importé. Le nouvel historique privé commence au premier relevé reçu par Supabase.

## Publication

Avant de publier la version signée, vérifier les résultats GitHub Actions, les signatures et sommes SHA-256, la télémétrie réelle de hashrate/température, ainsi que les statistiques en direct et le tableau privé du site.
