# BDLMiner V2 2.6.0

A security release, from a review of the firmware, the dashboard and the site. It
changes how a miner accepts updates, who may read or change it from a web page, and
the password of its setup network. Settings and statistics are kept.

## What changes for you

- **The setup network of a configured miner has its own password.** `MineYourCoins`
  remains the password of a miner that has no payout address yet. Once it has one, the
  miner opens its setup network (`BDLMinerV2-XXXX`) with a random password of its own,
  so that nobody nearby can reconfigure it while your WiFi is down. Read it on the
  miner's screen and QR code when the portal opens, on the USB serial console, or
  beforehand in the dashboard under *Settings › Network* (below *Fallback WiFi 1*):
  **on a board without a screen, note it there after updating.** Erasing everything
  brings `MineYourCoins` back.
- **The portal no longer shows the web password.** Leave the field empty to keep the
  current one, type a new one to replace it; the dashboard's settings remove it.
- **A NerdNOS whose temperature sensor does not read no longer mines.** See below.

## Updates

- **A signed update must be this board's firmware, at the announced version.** The
  release signature covers one firmware file, not the answer that announces it, and
  that answer's connection may be unverified. A signed image of another board, or of
  an older version, was therefore accepted. The updater now also requires the board
  and version every release image carries, and refuses the file otherwise.

## Dashboard

- **Changes only from the miner's own pages, harder to get around.** The miner is
  opened by its IP address, a local name (`bdlminer-xxxx.local`, `.lan`, `.home`…) or
  the name your router gives it (`bdlminer-xxxx.fritz.box`). After three requests
  under a name that is not the miner's, that last form is refused for an hour: a web
  page trying names to reach the miner can no longer find the right one. Open the
  miner by its IP address or `.local` name meanwhile.
- **`/api/stats` no longer names you to other sites.** Pages of your local network
  (the other miners' dashboards) read everything as before. A page of any other site
  gets the readings without the payout address, the WiFi name, the IP address, the
  other miners, the MQTT broker and the crash report. A dashboard opened under a name
  that is neither local nor the miner's own shows the same reduced view.

## Mining

- **NerdNOS: a corrupted answer of the ASIC could read past the job table.** The
  BM1397's answers are not protected by a checksum; a job number damaged on the serial
  line pointed outside the driver's 32 jobs. Such answers are now dropped.
- **NerdNOS: no temperature, no mining.** The 80 °C hard stop needs a reading. With an
  open or shorted sensor and the temperature limit at 0, nothing stopped the ASIC.
  Without a valid reading for 10 s it is now stopped whatever the setting, and starts
  again by itself once the sensor reads. Until now such a board mined at 25 % with a
  limit set.
- **Bitaxe Gamma 601: a failed start is tried again.** A start that failed with no
  safety limit involved (the chip not answering, a serial write refused) stopped mining
  until a restart at the first failure. It now gets the three automatic restarts an
  hour that a chip going silent while mining already had; a fourth failure stops it as
  before. Temperature, fan, supply and regulator faults still stop it at once.
- **Clock.** When NTP does not answer, the clock comes from the pool's job time. A
  time older than the firmware's own build is no longer used: it would make an expired
  certificate look valid.

## Site and tools

- The flash page's USB installer (ESP Web Tools 10.4.0) and the chat's QR code library
  are served by the site itself instead of a CDN: no page loads a script from another
  site.
- Fleet counts on the statistics page are written as numbers only; the fleet hub no
  longer fails on a non-ASCII token.

## Updating and validation

Use the signed GitHub updater or the matching `<board>-firmware.bin` through the local
dashboard. Factory images are for USB installation. Miners on 2.5.9 or earlier install
this version with their current updater; the new checks apply from this version on.

The native suite (with new regressions for each change above), 124 browser
regressions, the site and hub tests and the builds of all 12 board profiles pass. The
release pipeline tests, builds, validates the images and signs the firmware centrally.
**None of these changes was run on a board before this release**: the update check,
the setup network's password, the NerdNOS sensor stop and the Gamma restart are
verified by tests only. On a NerdNOS, check that the ASIC starts (the sensor must read
within 10 s of the start); on a Gamma, that it starts as before.
