# BDLMiner V2 2.5.4

Corrections des mises à jour depuis GitHub et des pages web, et suivi à distance par
adresse de portefeuille ; minage et écrans inchangés depuis la [2.5.3](v2.5.3.fr.md),
la mise à jour s’installe par le WiFi.

- **Les mises à jour depuis GitHub ne s’arrêtent plus sur « HTTP 618 ».** GitHub sert
  maintenant les fichiers des versions depuis un serveur qui exige un lien de
  téléchargement valable cinq minutes seulement, et répond à un lien refusé (expiré ou
  pas encore valide) par le code non standard 618. Le miner abandonnait alors pour cinq
  minutes. Il redemande maintenant tout de suite un lien neuf à GitHub, jusqu’à trois
  fois, et le journal explique ce qui s’est passé.
- **Téléchargements plus rapides et protégés.** Depuis le passage à Arduino-ESP32 3.x,
  chaque téléchargement depuis GitHub ouvrait une deuxième connexion sécurisée, non
  protégée : le client HTTP fermait celle que le firmware avait ouverte. Il utilise
  maintenant celle du firmware, ce qui divise par deux les poignées de main d’une mise
  à jour.
- **Suivi à distance par adresse de portefeuille.** Plus de clé à créer et à copier :
  dans **Réglages → Réseau → Suivi privé à distance**, active-le (et nomme le mineur) ; il
  envoie ses mesures sous son adresse de paiement, la partie avant un éventuel `.worker`.
  Sur [Mes mineurs](https://bdlglua.github.io/remote/), saisis la même adresse. La page
  reprend le style du site et peut retenir l’adresse sur l’appareil. Comme sur la page
  d’une adresse chez la pool, toute personne qui connaît l’adresse peut voir ces mesures ;
  une clé privée créée avant la 2.5.4 fonctionne toujours et les garde secrètes. Voir
  [le suivi à distance](../remote-access.fr.md).
- Pages web : la carte « Parc en direct » de l’accueil ne cache plus la première
  miniature ; une recherche sans résultat le dit ; la FAQ trouve « wifi » dans
  « Wi-Fi » ; le site, les démos et le hub Linux affichent le logo comme icône.
- Firmware : plus aucun avertissement du compilateur dans son propre code (appels
  dépréciés remplacés).

Un miner encore en 2.5.2 ou 2.5.3 peut avoir besoin de plusieurs essais pour télécharger
cette mise à jour (le problème corrigé ici) ; il réessaie tout seul toutes les cinq
minutes. Pour mettre à jour tout de suite, installe `<carte>-firmware.bin` de la version
par sa page web.

## Validation

Tous les tests hôte, outils et navigateur et toutes les compilations de cartes passent.
Le test des redirections couvre maintenant un lien refusé suivi d’un lien neuf, et le
nombre limité d’essais. Les réponses 618 ont été reproduites sur le serveur de fichiers
de GitHub avec un lien expiré (`618 jwt:expired`) et un lien modifié
(`618 jwt:signature-fail`).
