# BDLMiner V2 2.6.2

## Public statistics: Supabase migration

- Anonymous hashrate reports now go to the Supabase-backed BDLMiner public statistics collector, using verified HTTPS.
- The public website at https://miner.bdl-pool.com/stats.html now reads the same collector. The website change was deployed separately before this firmware release.
- The existing report payload stays minimal: firmware version, board, reported hashrate, report interval, supported coin, and optionally public pool group/model. Payout addresses, workers, and private pool hostnames are not included.
- The collector provides 5-minute historical samples. Anonymous reports are approximate miner counts and are not verified proof of actual work.

## Updating

Use the signed GitHub updater or install the matching `<board>-firmware.bin` from the device's local dashboard to preserve settings and statistics. `<board>-factory.bin` is intended for USB factory installation and can erase configuration.

## Validation and known limitations

- The Supabase backend returned HTTP 200 for its health and summary endpoints and HTTP 204 for valid anonymous report submissions. At least one real M5StickC Plus2 has successfully sent reports to the backend.
- CI validated the Supabase endpoint changes on the preparation branch's parent test PR. Final release workflow tests, signatures, images and deployment must pass before publishing.
- A real M5StickC Plus2 in the initial field test reported approximately 480-505 kH/s after formerly showing around 1 MH/s. **Root cause has not yet been confirmed.** Verify `/api/stats` fields `power_percent`, `limitation_reason`, `throttle`, `temp_c`, and `engines` before concluding there is a hashing-engine regression. This release does not claim to fix or improve hashrate.
- Firmware versions which still report to the legacy `api.bdl-pool.com:36018/report` require a compatibility relay or a firmware update to appear in the Supabase totals.
- Private remote monitoring, local pools and wallet/payout configuration are outside the scope of this migration.

## Signed release artifacts

The release workflow must complete all host/browser tests and per-board builds, then generate and sign factory and update images. Check the checksums and signatures in the resulting GitHub draft release before promoting this candidate to stable.
