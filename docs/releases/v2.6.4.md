# BDLMiner V2 2.6.4

## Private monitoring: Supabase migration

- Anonymous public hashrate statistics were migrated to Supabase in v2.6.3. This release completes the cutover by moving private **My miners** telemetry to Supabase as well.
- Optional **My miners** reports now go directly to a separate Supabase Edge Function. Address-based read access and 64-character private keys keep their existing behaviour; the raw address/key is never stored in the new tables.
- Public aggregate reports and private per-device telemetry are stored separately. Private names, pseudonymous device IDs and detailed readings never enter the public aggregate.
- The former SQLite/Caddy statistics host and Cloudflare compatibility relay are not required. Firmware older than 2.6.4 still points to the retired host and must be updated; no compatibility proxy is provided.
- The anonymous public report remains minimal: firmware version, board, hashrate, interval, coin and optionally public pool group/model. It does not include a payout address, worker, private pool hostname or device identifier.

## Updating

Use the signed GitHub updater or install the matching `<board>-firmware.bin` from the device's local dashboard to preserve settings and statistics. `<board>-factory.bin` is intended for USB factory installation and can erase configuration.

## Validation and known limitations

- The Supabase public collector returned HTTP 200 for health/summary and HTTP 204 for valid anonymous reports.
- The private Supabase endpoint was tested for key-based and address-based reporting, snapshot reads, history reads, key revocation and revoked-key rejection. Test telemetry was deleted after validation.
- CI must validate the final firmware and website commits, signed images and release workflow before publication. A successful backend test does not replace a physical device test.
- A real M5StickC Plus2 in the initial field test reported approximately 480–505 kH/s after formerly showing around 1 MH/s. **Root cause has not yet been confirmed.** Verify `/api/stats` fields `power_percent`, `limitation_reason`, `throttle`, `temp_c` and `engines` before concluding there is a hashing-engine regression. This release does not claim to fix or improve hashrate.
- Private history from the retired SQLite host is not imported. New private history begins when a miner first reports to Supabase.

## Release artifacts

Before publishing the signed release, verify the final GitHub Actions results, firmware signatures and SHA-256 checksums, physical hashrate/thermal telemetry, and the published website's live statistics and private viewer.
